# Настройки OpenCode Desktop 0.2.8

Настройки открываются кнопкой OpenCode Desktop внизу бокового меню или **⌘,**. Это отдельный экран с разделами слева, поиском и прокручиваемыми группами параметров справа. **«Вернуться в приложение»** и Escape возвращают в текущий чат; история и черновик не пересоздаются. Если изменены поля подключения, диктовки, помощника или подготовлена конфигурация OpenCode, выход предлагает остаться либо отбросить эти изменения. Ответ, завершившийся за экраном настроек, остаётся непрочитанным до просмотра чата.

В **«Общее»** находятся локальный адрес сервера и переход к управлению SSH-подключениями. Адрес применяется отдельной кнопкой подключения, без перезапуска OpenCode.

**«Сервисы помощника»** управляют локальным адресом CPU-контейнера CT205 через SSH-туннель и показывают живой статус и список доступных преобразований. URL сохраняется отдельно от адреса OpenCode и настроек GigaAM; допускается только loopback HTTP без пути и учётных данных. Перед сохранением можно проверить подключение. Через сервис PDF превращается в текст/страницы, видео — в кадры и звуковую дорожку, аудио — в фрагменты для отдельного GigaAM ASR. Форматы и пределы описаны в [руководстве по вложениям](ATTACHMENTS.md). MCP-серверы по-прежнему добавляются в разделе «MCP» после отдельного развёртывания.

В **«Внешний вид»** доступны:

- Системная, светлая и тёмная тема.
- Нейтральный, золотой, синий, фиолетовый, зелёный, коралловый или собственный HEX-цвет. Цвет текста на акцентной кнопке и цвет акцентных надписей подбираются для читаемости в обеих темах.
- Размер интерфейса 12–18 px, сообщений 12–24 px и кода 10–22 px. Размер кода распространяется на блоки ответа, вывод инструментов и файловые превью; шрифт терминального эмулятора остаётся отдельным фиксированным параметром.
- Обычная, широкая или полная ширина чата; обычный или свободный межстрочный интервал.
- Живой предпросмотр и **«Сбросить оформление»** (тёмная нейтральная тема, размеры 14/14/12, обычная ширина и интервал).

Оформление применяется сразу и хранится в локальных предпочтениях Desktop, отдельно от моделей и конфигурации OpenCode. Оно одинаково для локального и SSH-сервера. Старые предпочтения получают значения по умолчанию; некорректные цвета и размеры проверяются при загрузке. Для своего HEX-цвета есть отдельная кнопка применения.

**«Диктовка»** управляет ASR и имеет отдельные кнопки сохранения/отмены. На этой установке по умолчанию задан GigaAM v3 CPU: `http://192.168.31.59:8080/api/asr/v1/audio/transcriptions`, модель `gigaam-v3-e2e-rnnt`, язык `ru`. Это CT 201 `cpu-inference` на Proxmox. Приложение отправляет запись как OpenAI-совместимый multipart и вставляет полученный текст в черновик; при желании URL и модель меняются в UI. Ключ ASR остаётся в памяти процесса. В проверке с M4A (`audio/mp4`, тот же формат, который поддерживает нативный адаптер) сервер точно распознал «Проверка диктовки на компьютере» за 0,55 с обработки.

Разделы **OpenCode** показывают фактические инструменты, навыки и MCP-статусы из API выбранного сервера. В установленном нативном приложении можно править конфигурацию этого Mac для всех проектов или файл `opencode.json[c]` текущей локальной рабочей папки. При подключении к удалённому OpenCode этот Mac не редактирует удалённые файлы: инвентарь виден, локальная запись отключена.

- **Инструменты:** правила `allow` / `ask` / `deny` для отдельного инструмента в `permission`. «Наследовать» убирает только правило данной области. Сложные существующие правила показываются отдельно и не перезаписываются выбором простого значения.
- **Навыки:** обнаруженные `/skill` с описанием и путём; HTTPS-источники добавляются в `skills.urls`. Инструмент `skill` контролирует доступ к ним.
- **Плагины:** npm-пакет добавляется в `plugin`. OpenCode скачивает пакет через Bun при следующем запуске. Это исполняемый код, поэтому ввод ограничен именем npm-пакета; существующие локальные плагины и записи с опциями отображаются и сохраняются. UI не выдаёт факт сохранения за факт успешной загрузки/активации пакета.
- **MCP:** список серверов и текущий статус из `/mcp`; добавление удалённого HTTPS либо loopback HTTP endpoint без учётных данных в URL. Существующие локальные MCP записи не меняются при добавлении удалённого.
- **Агенты:** обнаруженные `/agent` и настройка `default_agent` в выбранной области. Конкретный агент по-прежнему выбирается в поле ввода чата.

Изменения сначала попадают в предпросмотр: UI перечисляет затронутые ключи, даёт проверить новые значения и отдельно нажать **«Применить»** или отменить. Для редактирования JSONC используется точечное изменение ключей: неизвестные поля и комментарии сохраняются. Перед записью нативная часть сравнивает исходный текст с текущим файлом, создаёт резервную копию и атомарно заменяет файл. При внешнем изменении предлагает перечитать файл. Если приложение видит работающую сессию, запись временно блокируется. Приложение **не перезапускает OpenCode автоматически**; новые значения применяются при следующем штатном запуске сервера.

Официальная документация: [конфигурация](https://opencode.ai/docs/config/), [инструменты](https://opencode.ai/docs/tools/), [навыки](https://opencode.ai/docs/skills/), [плагины](https://opencode.ai/docs/plugins/), [MCP](https://opencode.ai/docs/mcp-servers/).

**«Управление компьютером»** содержит существующее подключение Cua Driver, проверку разрешений и экстренную остановку. **«О приложении»** показывает версии Desktop/OpenCode, состояние соединения, событий и доступные агенты.

### Доступ к микрофону macOS

Диктовка начинается только по нажатию микрофона. Для подписанной сборки с Hardened Runtime требуется entitlement `com.apple.security.device.audio-input`; с 0.2.7 он входит в сборку вместе с описанием `NSMicrophoneUsageDescription`. После установки разрешите микрофон в системном диалоге, если он появится. Состояние доступа: **Системные настройки → Конфиденциальность и безопасность → Микрофон → OpenCode Desktop**. Локальная ad-hoc подпись может потребовать повторного согласия после обновления. Ошибка захвата объясняется по-русски отдельно от ошибок ASR; отмена не отправляет аудио на распознавание.

## Использование токенов

Настройки → «Использование» читает сохранённые сообщения только по запросу.
Можно выбрать последние 7 дней, 30 дней или всю историю, обновить расчёт и
сравнить расход по фактически использованным моделям. В расчёт входят обычные,
архивные и дочерние сессии текущего сервера OpenCode, а также чаты Pi,
зарегистрированные в Desktop. Если чтение части истории не удалось, экран
отмечает результат как неполный. Ни текст запросов, ни сводка не сохраняются.

Сумма токенов разбивается на вход, чтение и запись кэша, выход и неизвестную
категорию, если движок передал только итог. Reasoning является частью выхода.
Это показатели обработанных токенов, а не окно контекста, деньги или лимиты
провайдера. Удалённые чаты и другие, сейчас не подключённые серверы учесть
невозможно.
