# Обновления через Arvela Hub

Начиная с 0.2.54, клиент получает релизы с настроенного Hub: тот же HTTPS origin,
публичный сертификат и ключ устройства, что у общей библиотеки. Передача истории
может быть выключена — обновления от неё не зависят. Ключи не попадают в WebView,
URL, пакеты или логи. Для первого перехода с 0.2.53 требуется новая нативная сборка.

## Два типа обновлений

Каждый релиз содержит два полных подписанных пакета: готовый `dist` и исходники.
Клиент сравнивает отпечаток нативных файлов, зависимостей, ресурсов, capabilities
и конфигурации. Из сравнения исключён только номер версии приложения.

- **Зелёный кружок**: нативная часть совместима. Меняется локальный интерфейс;
  Rust, Node и сборка клиенту не нужны. Основной процесс, Pi и браузер продолжают
  работать. Перед перезагрузкой UI сохраняются настройки/вложения и ожидается
  подтверждение сообщений, которые уже отправляются. Новые отправки на время
  перехода блокируются; повторной отправки истории нет.
- **Жёлтый кружок**: нужно собрать нативную часть. Клиент проверяет Node.js/npm,
  Cargo и rustc, создаёт отдельную папку из проверенного снимка и запускает `npm ci`
  и Tauri build. Сборка идёт в фоне; её можно отменить. Установка разрешена только
  после завершения собственных агентов и диалогов. Она создаёт резервную копию
  настроек, очередей, вложений и журнала доставки. Нативный перезапуск не может
  сохранить работающий внутри процесса Pi — поэтому активные задачи не прерываются,
  а установка ждёт простоя.

Наличие проверяется при запуске и каждые 30 минут. Скачать, применить или назначить
установку после задач нужно явно. Кружок открывает Настройки → Обновления. Исчезновение
сервера не мешает текущей работе. Контрольная сумма и minisign-подпись с привязкой
версии проверяются до исполнения кода. Метаданные сервера сами по себе не дают
разрешения установить пакет; ключ проверки встроен в приложение.

Интерфейс обслуживается штатным локальным протоколом Tauri с прежними CSP,
capabilities, localStorage и IndexedDB. Удалённый сайт с правами Tauri не открывается.
Текущий и предыдущий интерфейсы сохраняются. Если React не подтвердит запуск за
30 секунд, происходит откат и перезагрузка только UI. Незавершённое горячее
обновление откатывается также при следующем запуске. Повреждённый/несовместимый
кэш не исполняется, используется встроенный интерфейс.

## Инфраструктура клиента

Для горячих обновлений достаточно установленной Arvela. Для нативных обновлений
пользователь подготавливает [зависимости Tauri](https://v2.tauri.app/start/prerequisites/)
и Node.js/npm, Rust/Cargo, доступ к npm/crates и свободное место для сборки.
Тулчейны, компиляторы и системные пакеты в Arvela не включаются и автоматически
не устанавливаются.

- macOS: Xcode Command Line Tools. Собирается `.app`; отдельный помощник ждёт
  завершения Arvela, заменяет bundle и открывает новую версию. Предыдущая `.app`
  остаётся рядом с установленной. Нужны права записи в папку установки.
  Используется локальная ad hoc подпись: без Developer ID невозможно обещать
  сохранение всех разрешений macOS между нативными сборками.
- Windows: инструменты сборки MSVC, WebView2 и требования Tauri. Собирается NSIS;
  помощник после выхода приложения запускает установщик в текущую папку установки.
  Конфигурация Arvela использует установку для текущего пользователя.
- Linux: зависимости WebKitGTK/GTK и Tauri. Для запущенного AppImage собирается
  AppImage, заменяется пользовательский файл. Для пакетной установки собирается
  deb либо rpm; установка вызывает штатный `pkexec` + dpkg/rpm и может потребовать
  системное подтверждение. Отсутствие polkit/системных зависимостей — явная ошибка,
  а не повод обходить ограничения ОС.

Ограничения: зависимости 15 минут, компиляция 40 минут, лог 8 МиБ; остановка
касается только созданной Arvela группы процессов/Windows Job. Лог сборки остаётся
локальным, путь отображается при ошибке. Кнопка очистки удаляет только собственные
папки сборок. Истории OpenCode/Pi и внешние серверы не удаляются и не перезапускаются.
Реальный выпуск на Windows/Linux должен проходить отдельную проверку на этих ОС;
успех тестов на macOS не заменяет её.

## Окно и трей

Закрытие основного окна скрывает его и вынесенный просмотр браузера, сохраняя
агентов. Открыть приложение или страницу обновлений можно из трея; на Mac также
работает повторное открытие из Dock. Полный выход — «Завершить Arvela» в трее:
интерфейс сохраняет состояние, затем штатно останавливаются собственные агенты.
Зависший UI не блокирует выход навсегда. При отсутствии системного трея окно
сворачивается, чтобы приложение оставалось доступно.

## Выпуск новой версии

Обычные `npm run build` и тесты ничего не публикуют. Официальная команда выпуска:

```sh
npm run release:hub -- stable
# либо preview
```

Перед запуском: актуализировать version в package.json/package-lock.json,
Cargo.toml/Cargo.lock и tauri.conf.json, выполнить проверки, просмотреть diff и
закоммитить изменения. Команда откажется публиковать грязное дерево. Она собирает
UI, берёт только Git-tracked файлы (без .pi/.local/секретных env), подписывает оба
пакета и загружает их в Hub по compare-and-swap текущего канала. После нативного
изменения клиент сам выберет сборку; после чисто UI изменения — горячий путь.

Переменные окружения передаются через приватное окружение оператора:

- `ARVELA_HUB_URL`: HTTPS origin настроенного Hub.
- `ARVELA_HUB_CA_FILE`: публичный PEM сертификат для частного CA.
- `ARVELA_HUB_ADMIN_TOKEN`: ключ администратора, не ключ обычного устройства.
- `TAURI_SIGNING_PRIVATE_KEY_PATH`: существующий приватный ключ релизов.
- `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`: пароль ключа, если задан.
- `ARVELA_RELEASE_NOTES`: короткое описание релиза.

Не помещать эти значения в репозиторий, URL или документы. Приватный ключ никогда
не передаётся Hub и клиентам. Публикуются подписанные данные; Hub их не исполняет.
Пара интерфейс/исходники становится видимой атомарно. Версия должна возрастать;
preview не допускается в stable. Новая версия ключа потребует доверенной нативной
миграции, подменить ключ через неподписанный ответ Hub нельзя.

## Сервер, API и восстановление

При обновлении сервиса копировать `releases.py` вместе с `server.py`, `memory.py`
и `web`. Доступны авторизованные GET `/api/updates`, `/api/updates/stable`,
`/api/updates/preview`, `/api/updates/artifacts/{sha256}`; POST `/api/updates` только
администратору. До чтения большого POST проверяется авторизация; одновременно
одна публикация и две загрузки, тело до 64 МиБ. Снимок до 24 МиБ, переносимые пути,
ограничения файлов и защита от symlink/traversal. Для релизов нужно не менее 256 МиБ
свободного места сверх входящего пакета. Хранятся последние 40 артефактов и текущие
пакеты обоих каналов.

Пакеты лежат отдельно от SQLite в `/var/lib/arvela-hub/releases`; их нужно включать
в файловую/полную CT резервную копию. Ежедневная SQLite-копия сама по себе пакеты
не содержит. Web UI → Обновления показывает каналы, версии и размеры пакетов.
Частные локальные кэши/логи/планы установщика находятся в данных Arvela
`update-runtime`; старые настройки — в `update-backups`. При сбое помощника
`last-install.json` содержит результат без секретов; предыдущая версия запускается
снова. Системная установка deb/rpm/NSIS зависит от штатных возможностей ОС.
