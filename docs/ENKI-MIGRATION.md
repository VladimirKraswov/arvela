# Переименование в Enki

Приложение называется Enki (Энки), защищённая сессия — «Мастерская».
OpenCode и Pi остаются названиями независимо установленных движков.
Их конфигурация, общая база сессий и исполняемые файлы не переименовываются.

## Совместимое обновление

Старые нативные клиенты отклоняют исходники с другим `productName`.
Переходные версии 0.2.82–0.2.83 ещё собираются в совместимом формате, но умеет проверять
и устанавливать Enki. Hub сохраняет этот подписанный переходный релиз для
старого маршрута `/api/updates/stable`. После его установки клиент читает
`/api/updates/enki/stable` и получает следующий релиз Enki. Preview независим.
Переходные пакеты защищены от сборки мусора. Подписи и ключ доверия не меняются.
`/downloads/latest` всегда указывает на последний релиз для ручной установки.

## Данные

При первом запуске нового нативного приложения, до загрузки интерфейса и агентов,
собственные данные переносятся из `opencode-desktop` в `enki` в прежнем родительском
каталоге: `$HOME/.local/share` на macOS, выбранном XDG data root на Linux,
`%LOCALAPPDATA%` на Windows. Используется атомарное переименование в одном
файловом разделе, а не копирование и удаление.

В старом месте остаётся ссылка (junction на Windows). Она нужна для абсолютных
путей, уже записанных движками в сессиях, вложениях и проектах. Это один и тот же
каталог: изменения видны через оба пути. Не удаляйте ссылку, пока старые сессии
ссылаются на неё. Новые удалённые рабочие папки создаются под `enki`; существующие
удалённые папки не перемещаются без проверки работающих процессов на том хосте.

Журнал намерения и системная блокировка позволяют завершить перенос после
аварийного выхода. Если создание ссылки не удалось, перенос откатывается.
Если оба пути содержат разные данные, миграция останавливается без объединения
и перезаписи. Работающий предыдущий экземпляр также блокирует перенос.

Постоянный bundle identifier и ключи существующих хранилищ пока остаются
идентификаторами совместимости: это сохраняет WebView localStorage/IndexedDB,
очереди, черновики, разрешения ОС и ключи в системном сейфе. Их нельзя просто
заменить строковой подстановкой: получился бы новый пустой профиль.
Старые имена допустимы только в явных адаптерах миграции, истории протокола,
закреплённых ключах и документации о переходе.

Миграция не отправляет промпты, не запускает старые задания, не меняет модели
и не удаляет пользовательские данные. Установка по-прежнему ждёт простоя;
публикация обновления сама по себе не перезапускает приложение.

## Имена пакетов и исходников

Начиная с 0.2.84 продукт и нативный пакет называются Enki/enki, основной
исполняемый файл — `enki`; `opencode-desktop` остаётся совместимым CLI-входом
для прежних MCP-регистраций. На macOS старый путь `.app` становится ссылкой
на `Enki.app`, не отдельной второй установкой. Отдельно установленное приложение
по этому старому пути автоматически не перезаписывается.
На Windows переносится также собственный профиль браузера из
`%USERPROFILE%/.opencode-desktop` в `.enki`, с junction для старых путей.
Private release operator переносит `~/.config/arvela-release` в `enki-release`,
сохраняя старые абсолютные пути файлов ключей через ссылку; `ENKI_*` переменные
предпочтительны, прежние `ARVELA_*` принимаются как совместимые псевдонимы.
Исторические исходные снимки тестов сохраняются побайтово: их контрольные суммы
являются частью доказательств прежних замеров, а не именем текущего приложения.

Второй переходный релиз 0.2.83 обновляет также алгоритм нативного отпечатка:
старый алгоритм исключал номер версии только у Rust-пакета с прежним именем.
Поэтому Hub сохраняет именно последний совместимый переходный релиз; клиентам
без перехода не предлагаются непроверяемые ими исходники нового пакета.

Стандартные инструкции мастерской и встроенного навыка управления компьютером
обновляются при запуске только при совпадении SHA256 с прежним опубликованным
шаблоном. Пользовательские правки и сторонние навыки не перезаписываются.

Движки сохраняют историческую строку каталога сессии. Для «Мастерской» нативный
слой проверяет, что старый и новый пути ведут в одну папку; интерфейс открывает
существующий ID по прежнему пути. Потеря настроек также не создаёт второй чат:
поиск проверяет оба подтверждённых каталога. Посторонний каталог не принимается.
