# Управление компьютером

Arvela подключает отдельный подписанный **Cua Driver 0.28.2** через локальный MCP. Драйвер работает с нативными окнами macOS, деревом доступности, снимками и отдельным визуальным курсором агента. Вычисления выполняет выбранная в OpenCode модель; отдельный облачный компьютер или ключ Cua не требуется.

## Включение

1. Установите официальный Cua Driver в `/Applications/CuaDriver.app` из [релиза](https://github.com/trycua/cua/releases/tag/cua-driver-rs-v0.28.2). На машине владельца он установлен из проверенного архива с подписью **Cua AI, Inc. / YCK386LBJ7**, bundle `com.trycua.driver`, notarization ticket.
2. В Desktop выберите «Этот компьютер», откройте **Настройки → Управление компьютером → Разрешения macOS…**. Cua Driver запросит Accessibility и Screen Recording. Эти разрешения выдаёт пользователь в macOS; агент их не переключает. На новых macOS может потребоваться отдельное подтверждение прямого захвата окна.
3. Нажмите **Проверить**, затем **Подключить**. Desktop сохраняет один MCP-сервер `cua_desktop` и путь к собственному навыку, сохраняя комментарии и остальные настройки JSONC с резервной копией/проверкой конфликта. Текущий проект получает MCP динамически, без перезапуска процесса OpenCode. Работающий OpenCode 1.18.18 кэширует глобальную конфигурацию: если в другом проекте инструменты отсутствуют, подключите их таким же действием после переключения. При следующем обычном запуске сервера конфигурация читается с диска. Desktop не перезагружает все проекты автоматически, чтобы не прервать чужую работу.
4. В обычном чате попросите выполнить конкретную задачу в конкретном приложении. Действия видны как вызовы инструментов, а поверх управляемого окна появляется курсор агента. Снимки и текст интерфейса получает выбранная модель — учитывайте это при выборе локальной или облачной модели.

Навык устанавливается в `~/.local/share/opencode-desktop/computer/skill/SKILL.md`. Для обнаружения нового навыка ранее созданному окружению OpenCode может потребоваться штатная перезагрузка его конфигурации. MCP-инструменты подключаются отдельно и доступны сразу после подтверждённого подключения.

## Контроль

- **Выключить** закрывает общий шлюз Desktop: последующие вызовы блокируются даже в ранее открытых MCP-подключениях. Конфигурация сохраняется с `enabled:false`.
- **Остановить управление Mac** дополнительно отзывает все текущие сеансы Cua Driver на этом Mac. Эта кнопка доступна и во время работы агента; она затрагивает все приложения, использующие тот же сервис Cua.
- Обычная кнопка остановки ответа OpenCode останавливает агента. Она не заменяет отзыв активного управления драйвером.
- Шлюз предоставляет только инструменты наблюдения и фоновой работы с конкретным окном. Инструменты принудительного завершения приложений, изменения конфигурации драйвера, записи экрана и управления полным рабочим столом не выдаются модели. Permission-check через MCP всегда выполняется без системных запросов доступа.
- Окно должно находиться на текущем рабочем столе (Space) macOS. Окно на другом Space может быть видно на снимке, но драйвер отказывает во вводе с `off_space_or_ax_unresolved`. Перенесите/откройте его на текущем рабочем столе. Фоновые действия не гарантированы для каждого контрола/приложения. При `background_unavailable` агент должен сообщить ограничение; шлюз не переключает управление на физическую мышь. Это не обещание полного совпадения с Codex.
- Интеграция первой версии относится к этому Mac и локальному OpenCode. При выбранном SSH/LAN-сервере установка локальных команд в него заблокирована. Подключения браузерных профилей, отдельная DOM-интеграция и удалённый рабочий стол не добавлены.

## Устройство

OpenCode запускает установленный бинарник Desktop с `--computer-mcp`. Этот режим не создаёт окно приложения: он проксирует MCP stdio к официальному драйверу, фильтрует набор инструментов и проверяет локальный выключатель перед каждым вызовом. Изображения сохраняются; у инструментов действий цель упрощена до обязательных PID и ID окна. Структурированные результаты дополнительно включаются текстовым JSON-блоком: OpenCode 1.18.18 иначе скрывает от модели PID, ID окон и токены элементов. Целевые PID/окна берутся из свежего наблюдения. Драйвер сохраняет собственную macOS identity и разрешения при обновлениях Desktop. Телеметрия драйвера в этой установке отключена; история действий/запись экрана не включены.

Основа и ограничения: [Cua Driver](https://github.com/trycua/cua/blob/main/libs/cua-driver/README.md), [контракт фоновых действий](https://github.com/trycua/cua/blob/main/docs/content/docs/reference/cua-driver/contracts.mdx). Драйвер обновляется независимо от OpenCode и Desktop; проверена указанная версия, совместимость будущих версий требует проверки.

Экстренная остановка отзывает runtime драйвера. Следующее явное нажатие «Подключить» закрывает только такой отозванный runtime и создаёт новый с обычной политикой. Вызовы модели не могут перезапускать драйвер; другие отказы доступа не обходятся. Готовность проверяется по разрешениям драйвера, а не только по MCP-соединению.
