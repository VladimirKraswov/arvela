# Общая память проекта

Arvela 0.2.31 хранит в вашем Hub проверенные факты и порядки действий для проекта.
Раздел **Контекст задачи → Память проекта** одинаков для OpenCode и Pi.
Это сведения, а не новый набор системных инструкций: AGENTS.md, политики проекта
и контрольные записи остаются авторитетными. Автоматического добавления этих
сведений в промпты, обучения моделей или изменения навыков в этой версии нет.

## Связать компьютеры

1. Откройте папку и включите Hub в общей облачной библиотеке.
2. Создайте проект памяти с коротким названием. Отдельно подтвердите привязку папки.
3. Скопируйте полный код проекта (UUID) на другой компьютер.
4. Там откройте соответствующую папку, проверьте код и подтвердите показанный проект.

Совпадение имён папок не объединяет проекты. Сервер выполнения и абсолютный путь
остаются в локальном IndexedDB; Hub получает только UUID и название. Привязка не
зависит от выбранного агента. Другой Hub/сертификат или сервер исполнения требует
явной привязки; обновление приложения сохраняет существующие идентификаторы данных.
Переименование/перепривязка и удаление проекта памяти пока не имеют интерфейса.

## Проверить запись

Сначала сохраните карточку результата задачи и примите её. Затем нажмите
**Предложить в память проекта** либо выберите принятый результат в разделе памяти.
Проверьте и отредактируйте название, содержание, вид записи и срок (7–365 дней).
Сохранение создаёт кандидата; только отдельное **Одобрить запись** делает его актуальным.
Указанные пользователем проверки не превращаются в независимо выполненные тесты.
Новая запись требует разрешения передачи текстов в Hub; чтение и оценка существующих
записей доступны без передачи нового текста. Черновики сохраняются при закрытии
панели в текущем запуске приложения, но не после выхода из приложения.

Если источник изменился после подготовки предложения, сохранение отказывается
привязать старый текст к новой ревизии. Отмените черновик и выберите свежий принятый
результат. Повторный запрос после неизвестного сетевого исхода использует тот же UUID;
конфликт сохранённой версии не перезаписывает запись. Одобрение и снятие актуальности
также требуют точного совпадения ревизии.

## Актуальность и границы

Источник — SHA256 локального идентификатора результата, его ревизия, SHA256
цели/критериев/проверок/итога, агент и устройство-источник. Локальные пути,
адрес сервера и содержимое файлов в этих метаданных не передаются. Содержимое
предложения фильтруется от известных секретов и абсолютных путей на клиенте и Hub;
автоматическая фильтрация не гарантирует удаления всех персональных данных.

Изменение ревизии источника или снятие принятия делает связанные записи
неактуальными **после подключения и синхронизации устройства-источника**.
Проверка происходит при изменении карточек, открытии панели, возвращении фокуса
и раз в минуту. Отключённое устройство не может сообщить изменения немедленно;
сведения другого компьютера показывают последнюю известную ревизию.
Просроченные кандидаты и одобренные записи отображаются как «Срок истёк»;
сервер не разрешает одобрить их. «Снять актуальность» оставляет текст для аудита.
Истечение срока означает прекращение актуальности, а не удаление текста.
Память и её версии сохраняются отдельно от автоматически очищаемой истории чатов,
аналогично версиям библиотеки. Не используйте память для секретов.

Hub Web UI → **Память проектов** позволяет посмотреть UUID, записи, источник,
ревизии и сроки, отдельно одобрить кандидата или снять актуальность. Все ваши
подключённые устройства входят в один доверенный личный аккаунт; это не система
раздельных прав доступа для нескольких пользователей.

## Реализация

- `src/memory/projects.ts`: локальная атомарная CAS-привязка папки к UUID, до200
  привязок; без эвикции чужих данных.
- `src/memory/client.ts` / `Runtime.tsx`: только метаданные актуальности, без модели
  и агентского цикла; фоновая проверка раз в60секунд.
- `services/hub/memory.py`: `/api/memory`, SQLite транзакции, до200 проектов и200
  записей на проект; кандидаты/одобрение/неактуальность, отдельный журнал версий.
  В журнале устройство оценившего записывается отдельно от владельца источника.
- Нативный прокси ограничивает пути, поля, объём и согласие на передачу текста;
  использует существующий HTTPS/закрепление сертификата/системное хранилище ключа.
- Никаких Git remote URL, программного исполнения записей, автоматического
  предложения фактов моделью, переписывания skills или обучения.

Общий поиск через MCP и автоматическую подготовку контекста предусматривает M41.
Перед включением потребуются сравнения качества и времени с проверками M39.
Живая Windows/Linux-проверка нового UI остаётся отдельной; Mac и изолированные
тесты имитируют перенос UUID между разными путями, но не заменяют её.
