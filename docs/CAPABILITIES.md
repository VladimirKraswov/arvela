# Общие навыки и инструменты — Arvela 0.2.24

Настройки → **Навыки и инструменты** — один каталог для OpenCode и Pi.
Есть область «Весь компьютер» и дополнительные источники/сервисы «Этот проект».
Общие записи в проекте показаны только для чтения: изменять их нужно в общей
области. Идентификаторы не должны пересекаться между областями.

## Навыки

Навык — каталог `<name>/SKILL.md`, при необходимости со скриптами и примерами.
Для общего источника лучше использовать `~/.agents/skills` или `.agents/skills`
проекта. Эти стандартные каталоги оба агента обнаруживают самостоятельно.
Можно подключить любой существующий каталог абсолютным путём через UI.
Desktop добавляет его в `skills.paths` OpenCode и передаёт Pi через `--skill`;
файлы навыков не копируются и не редактируются. Поэтому исправление навыка
остаётся в одном исходном файле. При изменении пути подключённого источника
выключите старую запись и добавьте новую с другим идентификатором.

Для переносимости соблюдайте правила OpenCode: обязательные YAML `name`
(1–64 символа, строчные буквы/цифры с одиночными дефисами, совпадает с каталогом)
и `description` (1–1024 символа). Указывайте реальные программы и зависимости
в тексте навыка. Навык с вызовами конкретного плагина одного агента может
потребовать адаптации даже при одинаковом формате SKILL.md.

Desktop читает только метаданные. Он ограничивает просмотр 3000 записями,
глубиной 8 и файлом 64 КиБ, не обходит ссылки и сообщает об ограничении.
Это дополнительный обзор, а не замена собственного discovery агентов:
каталог также дополняется ответом OpenCode `/skill` и `get_commands` уже
запущенной Pi-сессии. Наличие файла не означает, что агент его обнаружил,
что разрешения позволяют использовать его или что его зависимости установлены.
Текст навыка загружается самим агентом по необходимости.

Отключение подключённого источника убирает только добавленный Desktop путь.
Пути пользователя и стандартное автообнаружение агентов сохраняются.
Если тот же путь независимо подключён самим пользователем, Desktop его не удаляет.
Из уже использованного контекста текст навыка не исчезает: для нового набора
переоткройте процесс Pi или начните новый чат при необходимости.

## Общие исполняемые инструменты

Переносимый инструмент живёт в **MCP-сервисе**. Desktop хранит одну спецификацию
подключения, OpenCode использует собственный MCP-клиент, а Pi получает небольшой
адаптер, зарегистрированный через его штатный API расширений. Ещё одного цикла
агента нет. Оба получают имена `mesh_<service-id>_<tool-name>`.

Поддерживаются:

- **stdio**: абсолютный путь к программе и JSON-массив аргументов. Shell не
  используется; для npm-команд укажите Node и JS-файл. `.cmd`/`.bat` напрямую
  не запускаются. Сервис получает cwd реального проекта. Указанные имена
  переменных берутся из окружения запущенного Desktop, значения в реестр не
  записываются. Finder/Windows launcher могут не наследовать окружение терминала.
- **Streamable HTTP**: HTTPS или loopback HTTP, без секретов/query/fragment в URL.
  Необязательный Bearer хранится в OS vault и передаётся нативным мостом через
  окружение только нужному HTTP-клиенту. UI не читает сохранённый токен обратно. Смена токена меняет несекретную ревизию подключения, поэтому старая Pi-сессия требует переоткрытия.
  При изменении URL проверьте назначение токена; можно убрать авторизацию в форме.

Общий мост не поддерживает OAuth/SSE, MCP resources/prompts и серверную sampling.
Такие подключения остаются в собственных настройках OpenCode и не выдаются за
доступные Pi. Нативные OpenCode-плагины/инструменты и Pi-расширения не переводятся
автоматически между агентами. Браузер остаётся отдельным общим сервисом с
существующими режимами, профилем и защитой координат; каталог содержит переход
к его настройкам. Встроенные инструменты и разрешения агентов сохраняются.

MCP roots передают рабочий каталог серверу, **это не OS sandbox**. Используйте
сервисы, которым доверяете; права их процесса определяет операционная система.
Подтверждения инструментов выдаёт соответствующий агент и существующий Pi gate.
Desktop не добавляет `allow` и не отменяет разрешения ради унификации.

## Установка, состояния и применение

Для MCP один раз нажмите **Установить мост**. Требуется настроенный Node (тот же
поиск/явный путь, что у браузера/Pi) и npm. Проверенный абсолютный путь Node сохраняется для запуска моста из Finder/Windows launcher; после изменения явного пути нажмите «Проверить мост». Закреплён SDK 1.32.0, `npm ci` по
lockfile, без install scripts и второго Chromium. Установка ограничена 180 с,
собственные процессы останавливаются при выходе. Для навыков MCP SDK не нужен.

При сохранении и перед отправкой Arvela синхронизирует только свои
`mesh_*` записи и добавленные пути, сохраняя JSONC-комментарии, сторонние MCP,
провайдеры, плагины и разрешения. Чужая запись с тем же именем блокирует применение
вместо перезаписи. Записи сохраняются через проверку ожидаемого содержимого,
резервную копию и атомарную запись. Если запись сохранена, но синхронизация
движка не завершилась, UI сообщает ошибку и позволяет перечитать/подключить снова.
Отсутствующий OpenCode не мешает Pi; после появления OpenCode настройки
подхватываются при подключении/следующей отправке.

**Проверить MCP** подключается и читает список инструментов, не вызывает их.
**Обновить статус** читает действительные каталоги/соединения. Ответ probe,
наличие SDK и наличие SKILL.md не подменяют подтверждение конкретного агента.
OpenCode подтверждается его API; Pi — отчётом адаптера текущего процесса с
ревизией спецификации. После изменения спецификации уже зарегистрированный
инструмент Pi и старый прокси отказывают в вызове до переоткрытия подключения.
Текущую Pi можно явно переоткрыть без удаления истории; новое сообщение создаст
процесс с актуальным набором. Во время работающих агентов изменение подключений
заблокировано. Неуспешное действие автоматически не повторяется.

Каталог работает с локальным Desktop/OpenCode. При SSH сохраняется управление
удалённым OpenCode в его штатных разделах; локальный Pi не подключается к
удалённому проекту автоматически.

## Хранение и проверки

Нативный каталог: `capabilities/global.json`, `capabilities/project-<hash>.json`
и `capabilities/runtime` внутри app data. Stable identity не меняется:
macOS `~/.local/share/opencode-desktop`, Linux — разрешённый XDG data root,
Windows `%USERPROFILE%/.opencode-desktop` (общий с браузером профильный корень, вне перенаправления AppData в MSIX). Остальные данные Desktop сохраняют прежний `%LOCALAPPDATA%/opencode-desktop`. Реестры/секреты в Git не попадают.

Автоматические тесты проверяют сохранение чужой конфигурации, конфликты,
неподтверждённые статусы, ожидание/ошибки и отказ устаревшим инструментам.
Opt-in `node src-tauri/resources/shared/test/acceptance.mjs <absolute-runtime>`
использует настоящий SDK и установленный Pi 0.85.1: метаданные без вызовов,
JSON Schema-валидацию, выполнение только собственного fixture, cwd, отсутствие
повторения и отказ после отключения. Он не отправляет модельных запросов и
не меняет пользовательские сессии. Live Windows/Linux-проверки этого релиза
отдельно остаются обязательными: проверка на Mac не доказывает их прохождение.
