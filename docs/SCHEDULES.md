# Таймеры и наблюдение

Enki 0.2.107 расширяет существующий планировщик, сохраняя прежние повторные
задания. Общий MCP «Таймеры Enki» автоматически добавляется в каталог инструментов
OpenCode и Pi. Для него нужна нативная версия 0.2.107; общий MCP-runtime должен быть
установлен. Отключённое или изменённое пользователем подключение сохраняется.
На удалённом агенте нужен доступ к соответствующей Enki: локальный путь не
подменяет удалённую инфраструктуру. Агент честно сообщает о недоступном инструменте.

## Из чата

«Следи за завершением сборки» — агент выбирает разумный интервал и сохраняет
самостоятельный запрос проверки с условием завершения. «Сделай через час» —
разовое пробуждение через 60 минут. «Больше не следи» — агент перечисляет таймеры
этого чата и удаляет нужный. Он подтверждает создание только после успешного ответа
инструмента. Интервал — от минуты до семи дней; точное время задаётся Unix milliseconds.
Агент получает краткую инструкцию при обычной отправке, уточнении и пробуждении,
в том числе после сжатия контекста. Полноценное смысловое понимание просьбы и
выполнение условия завершения остаются обязанностью выбранной модели.

`desktop_schedule` принимает явные `directory` и `session_id`, действия `list`,
`create`, `remove`, `pause`, `resume`. Создание требует `title`, `prompt`,
`request_key`; режим `once` или `repeat`, интервал `minutes` (по умолчанию 15),
необязательное `run_at` для первого запуска. Один `request_key` в том же чате
возвращает существующее задание; изменённый запрос под тем же ключом отклоняется.
При необходимости можно явно указать `provider_id` и `model_id`; иначе берётся
модель целевой сессии без переключения видимого чата. Модель и профиль сохраняются
с заданием; недоступная модель не заменяется автоматически другой.

Отдельный `--schedule-mcp` открывает только инструмент расписаний, а не управление
разрешениями или отправку произвольных немедленных запросов. Unix использует
приватный сокет; Windows — случайный порт только 127.0.0.1 и случайный 256-битный
токен в локальном дескрипторе профиля. Проверка токена и ограничения размеров
сообщений общие с существующим control plane. Никакого LAN listener нет.

## Выполнение и управление

В боковом меню **Таймеры и наблюдение** видны задания всех подключений этого
устройства, сохранённый запрос, модель, папка, время, результат последней отправки,
пауза, возобновление и удаление. Расписание открытого чата также есть в контексте
задачи. Это локальные таймеры устройства, не распределённый Hub-планировщик:
одно и то же наблюдение, независимо созданное на двух устройствах, выполняется
на каждом из них. UI-сброс/очистка профиля удаляет локальное расписание.

Пока чат занят, ожидает ответа/разрешения или содержит пользовательскую очередь,
плановый запрос не отправляется. Работает существующий путь доставки с проверкой
исходного сервера, модели, каталога инструментов, Hub readiness/reservation и
журналом отправки. Очередь пользователя имеет приоритет; черновик не затрагивается.
Неопределённая доставка приостанавливает таймер: автоматического повтора
потенциально принятого запроса нет. Сбой хранилища останавливает планировщик.
Два окна одного профиля используют существующую lease; изменения перечитываются.

Разовый таймер выключается после принятия запроса агентом — это не утверждение,
что сама задача уже успешно завершена. Просроченный разовый таймер после открытия
выполнится, когда чат будет готов; пропущенные повторные проверки не накапливаются.
Полный выход выключает пробуждения, скрытие в трей сохраняет их. Компьютер должен
бодрствовать; Enki не включает его и не будит macOS/Windows/Linux из сна.

Индикатор занятой сессии — лоадер; ожидающей следующего пробуждения — часы.
Внимание/ошибка имеют свой значок. Фиксированная область не сжимается длинным
названием. Общий requestAnimationFrame-clock обновляет только transform подключённых
DOM-индикаторов, пока страница видима, не React-состояние; перемещение строк не перезапускает отдельные
CSS-анимации. При системном reduced motion вращения нет намеренно; скрытое окно
не расходует кадры, при возвращении все индикаторы продолжают общий ритм.

## Проверка

Покрыты одноразовая доставка после перезапуска, ожидание занятого чата,
совместимость прежних записей, ключи создания, запрет чужого scope при удалении,
управление из общего списка, точное скрытие собственного контекста Pi, общий
clock при перестановке/пересоздании DOM и reduced motion. Реальный WebKit preview
на изолированных данных проверяет длинные названия, паузу/удаление и обе темы;
никаких запросов владельца или inference в проверке не запускалось.
Нативные тесты проверяют изолированный список MCP и сохранение отключённых
пользовательских регистраций. Windows/Linux live-проверка новой версии отдельно.
