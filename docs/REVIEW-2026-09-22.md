## Repair first: proven release blockers

### R1 — P1: new session disables live events

`src/state/store.ts`: `handleEvent(session.created/deleted)` calls `refreshSessions()`; its default path increments `directoryGeneration`, invalidating the already attached stream. Every later `onEvent` returns at the generation guard, without reconnecting. A new conversation can therefore appear stuck despite the backend working.

Acceptance: review test R1 passes; adding/deleting/refreshing a session must leave same-project streaming active; a genuinely old project stream must still be rejected. Separate list-request generations from connection/project lifecycle. Add a permanent regression test.

### R2 — P1: selected agent is ignored in existing session

`getAgentChoice()` prioritizes `active.agent` over `prefs.agentChoice`. Selecting another agent in the composer returns the old agent and can submit to the wrong one.

Acceptance: R2 passes, selected agent is shown and sent in the next prompt; valid saved/session/default precedence is explicit and tested. Discover configured `default_agent`, default model and supported effort from scoped configuration instead of selecting the first provider/agent. The existing unused `defaultAgent()` method is not enough. Qwen/Medium must be respected on this machine without hard-coding them for all users. Exclude subagent-only agents from primary selection.

### R3 — P1: late async results cross project boundaries

`createSessionNow()` unconditionally adds/selects the result even after directory change. R3 reproduces project A's session appearing selected while directory B is active. `sendPrompt()` captures some values before await but reads the agent after it, enabling mismatched submission context. ChangesTab also lacks a stale-response guard.

Acceptance: R3 passes; bind endpoint/directory/session/model/agent/draft identity at submission. Late create/history/list/diff/metadata responses must not mutate another selection. Test both A→B switching and endpoint changes with deliberately reordered responses. Don't orphan or delete a session already created by an accepted request.

### R4 — P1: reconnect leaves a finished task marked busy

Resync updates `statuses`, while UI preferentially reads the old `chat.sessions[id].status`; `applyHistory` explicitly keeps that old state. R4 reproduces stale busy despite authoritative idle.

Acceptance: R4 passes; reconnect reconciles statuses and pending requests, with missing entries interpreted according to the actual API (idle sessions may be absent). Avoid a concurrent history snapshot overwriting newer live deltas. Test lost-connection completion, pending question/permission and snapshot/live-event races.

### R5 — P1: accepted send erases a newer draft

After prompt acknowledgement, sendPrompt unconditionally deletes the current session draft and new-conversation draft. R5 shows user text entered while awaiting 204 disappearing. Composer failure handling also restores into the *currently selected* draft, which may now belong to another session.

Acceptance: R5 passes; only clear/restore the exact submitted draft revision in its original slot. New text and other-session drafts survive success/failure/project switches. Never automatically resubmit an ambiguous request; block duplicate Enter while busy or implement an explicit, deduplicated queue.

### R6 — P1: terminal discards real shell output

The old checkpoint assertion “string frames are control echo; ignore” is false for the installed server. The independent live probe received:

- Text frames with shell prompt and `REVIEW_STRING_42` / `REVIEW_BINARY_43` command output.
- One binary frame starting `0x00` followed by `{"cursor":45}` control metadata.
- Both text and byte input produced output on the probe.

`TerminalPanel` currently ignores every string frame. This explains the blank terminal; it is not merely an xterm DOM-inspection problem.

Acceptance: render real text output, parse verified control/binary variants without corruption, test ANSI and split UTF-8, inspect `pwd`, echo, resize, Ctrl-C in the actual terminal UI. Preserve replay cursor/lifecycle as supported. Don't attach to or kill a random user PTY: track shells created/explicitly selected by this app; verify project ownership; clear timers and stale callbacks on detach. Do not swallow 401/403 token errors as ordinary protocol fallback. Correct false protocol claims in comments/checkpoint/docs.

## Next: missing behavior and launch reliability

### R7 — P1: first launch and native development

`App` fires `connect()` and `refreshProjects()` concurrently; refresh exits while phase is connecting and no later successful connect loads projects. A fresh profile shows an empty project list until manual refresh. Chain startup intentionally and handle React StrictMode cleanup/duplicate effects.

Both Vite config and Tauri devUrl still name 1420, which is occupied by another project. Choose a consistent dedicated port for this app (1425 currently serves it); never stop TinyCAD or attach the wrong Vite origin to native privileges. Test packaged app independently of Vite.

### R8 — P1/P2: actual review/history semantics

- Session diff normally provides `before` and `after`; the UI labels any such file without `patch` as binary/undisplayable. Generate a real text diff, and detect binary explicitly. Add new/deleted/renamed and pre-existing-change fixtures.
- History fetch is limited to 200 and drops pagination; provide a way to load older messages without losing new live ones. This matters directly for large tasks.
- Archive has no restore UI; archived IDs remain in persisted last-session state. Implement archive view/restore and clean selection on archive/delete without deleting user histories.
- Sidebar pending indicator looks up a session ID in maps keyed by request ID; use request.sessionID. Synchronize status precedence with R4.
- Model/agent/effort selection must be scoped and actually applied. A newly selected model should not inherit an unsupported effort value.

### R9 — P2: compatibility, errors and usable controls

A numeric major range 1..2 is not evidence of API compatibility. Check required endpoints/capabilities and document actually tested 1.18.18; missing optional features must degrade explicitly. Invalid endpoint input must be rejected visibly, not silently redirected to a different localhost server. Capture a connection generation before changing endpoint, cancel prior streams/requests even when new health fails, and avoid mixing server-owned IDs/state.

Exercise real permission/question flows, exclusive single-choice versus custom answers, stop/abort/error, long reasoning, disconnect and reconnect, keyboard focus/dialogs, dark/light, narrow window. Normal `tool-calls` is not a failed finish. Review unhandled promises and hidden errors. Required M1–M6 capabilities in ROADMAP remain the acceptance contract; don't mark unchecked requirements completed merely because components exist.
