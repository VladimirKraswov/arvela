# Этап 2: воспроизводимые испытания — 2026-10-08

Полностью автоматический сравнительный прогон: 12 синтетических задач × OpenCode/Pi × два повтора = **48 испытаний**, 47 успешных. Общая длительность — 444.9 секунды. Вмешательств пользователя во время прогона — 0.

OpenCode 1.18.18, Pi 0.85.1, облачная `deepseek-flash`, запрошенный Medium, фактический High по политике DeepSeek. Оба агента использовали один ограниченный backend инструментов и одинаковые настройки запросов; навыки отключены. Последовательный порядок: OpenCode→Pi в первом повторе, Pi→OpenCode во втором. Локальные модели и активные чаты не использовались.

| Агент | Независимо проверенные результаты | Медианное затраченное время, все попытки | Входные токены | Выходные токены | Из входных — чтение кеша |
|---|---:|---:|---:|---:|---:|
| opencode | 23/24 | 7.69 с | 401 778 | 19 832 | 356 480 |
| pi | 24/24 | 7.58 с | 152 493 | 24 258 | 121 597 |

Вход включает кеш; последний столбец — его часть, а не дополнительные токены. Провайдер вернул usage для всех 311 запросов; всего 598 361 токен, включая 478 077 кешированных входных токенов. Сумма включает внутренние запросы CLI, например генерацию заголовка, поэтому может отличаться от видимых шагов агента. Стоимость не вычислялась по нулевым ценам custom-provider.

**Код и восстановление:** один неуспех у OpenCode в первом `stale-edit`: результат не прошёл внешние проверки уникальной, безопасной замены. Во втором повторе задача прошла; Pi прошёл оба повтора. Исходный кандидат первой попытки был удалён вместе с временным проектом, поэтому точную причину из этих данных утверждать нельзя. После этого стенд дополнен сохранением синтетических кандидатов с SHA256 для будущего разбора.

**Браузер:** 12/12 успешных испытаний. Оба агента сохранили скидку только нужному товару, исправили отвергнутый ввод и восстановились после принудительного изменения viewport/прокрутки. Каждый агент получил два отказа по устаревшему состоянию за два повтора и продолжил с новым наблюдением. Это реальные действия в отдельном Chromium, но через refs быстрого режима: мышиная эмуляция и packaged UI здесь не измерялись.

## Воспроизводимость и ограничения

Исходный стенд полного сравнения: `60a8661ace72b96329c9196e767bfcfea9187a3a`. SHA256 всех шести исполняемых файлов сверены с этим коммитом. [Неизменённый JSON со всеми попытками и ревизиями](paired.json). Старое поле schema 1 `verifiedSeconds` — затраченное время до завершения проверки, включая неуспех; наличие проверенного результата определяется только `passed`. В schema 2 отдельно записываются elapsed и время до успешного результата; для неуспеха последнее равно null.

В предварительных smoke-прогонах исправлены ошибки стенда: разрешение реального пути временной папки в Node, формат env-ключа Pi, лишнее JSON-кодирование текста файла, явный путь Chromium и слишком низкий лимит запросов для браузерной задачи. Неудачные предварительные прогоны сохранены отдельно и не включены в парную таблицу. После полного сравнения бюджетный отказ сделан постоянным HTTP 403, чтобы агент не тратил время на повторные обращения при исчерпанном лимите; эта ветка проверяется отдельно.

**Вывод:** обе связки решают простые задачи с почти одинаковым временем. Pi отправил меньше входных токенов в этом стенде, однако агенты имеют разные системные инструкции и внутренние запросы — это не доказательство универсального преимущества Pi. Два повтора и маленькие задачи не доказывают качество на больших проектах. Это исходная точка для оценки памяти/поиска контекста M40/M41; улучшение допускается только после повторения тех же задач и добавления более сложных сценариев. Нельзя выводить из неё скорость или качество локальной Qwen.
